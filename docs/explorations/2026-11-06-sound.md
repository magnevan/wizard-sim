# Sound, stage 1

The game had no audio. This is the first pass: an engine, a first set of sounds, and a page to rate them. The user's direction, in their words:

> I think Magicka is a good model for sound, we want a similar feel. In general I prefer free sound libraries or packs, and we can use local tools to tune the sounds for variations (top of mind variations could be things like number of runes, or environment (cave vs outdoor), interactions with other elements maybe, sounds behind walls). We can also try out AI sound generation. I imagine this is particularly helpful for things like narration that's too custom, but we can also see if we prefer it for sound effects.

**Nobody has heard any of this yet.** Claude can't listen. Everything below that says a sound "works" means it measured correctly. Whether it sounds good is for the Sound Gallery (`tools/sound-gallery/`).

## What it should feel like

Magicka's sound, as recalled *(unverified, from memory)*: lively, punchy, slightly comic and exaggerated, with big readable elemental sounds rather than gritty realism.

In the hands: every rune you queue blips, and the elements make a scale, so a queue is a small tune you learn without trying. A big spell sounds big before you see it land.

For a co-op partner (pillar 3): you should know what your friend just did without looking. The shape says what they did and the timbre says what they did it with. A rising breath then a thud off to your left, in Fire, means a patch is about to burn over there. That's the reason for the design below, more than the saving in recordings.

## The design: sound is built the way spells are

Each element is a layer, and each cast shape is a structure. Compose the two and you have the spell, so 9 layers and 9 shapes cover all 678 spells.

**Element layers** (`audio/recipes.ts`, `ELEMENTS`): each has a body (what it's made of, sustained), an attack and an impact.

| Element | Body | Attack | Made from |
|---|---|---|---|
| Water | Rushing water, a gurgle under it | Splashes | Commons |
| Life | A warm open chord, wind chimes | Single chimes | Code + Commons |
| Shield | A low humming field | Struck bell and plate | Code + Kenney |
| Cold | Frost shimmer, creaking ice | Breaking glass | Code + Commons + Kenney |
| Lightning | A hard electric buzz | Crackling zaps; a thunder crack on impact | Code + Commons |
| Arcane | Detuned, slowly turning saws | A falling, ringing bolt | Code + Kenney |
| Sigil | Thin shimmer | A glassy rune tone, a gong | Code + Commons |
| Fire | A jet roar and crackling flame | A burst of flame | Kenney + Commons |
| Earth | Tumbling gravel | A pick on rock | Commons + Kenney |

**Cast shapes** (`SHAPES`): every sim shape falls into one of nine.

| Shape | Structure | Sim shapes |
|---|---|---|
| Force | One quick shove | swing, palm, imbue, blink |
| Spray | Soft start, then a held rush | spray, shards |
| Beam | A hard strike-up, then a held line of tone | beam, arc |
| Missile | Thin launch, a whoosh, then it lands in its element | missile |
| Nova | Everything at once, a sub thump, a falling tail | nova, quake, discharge, ring, motes, orbitals |
| Place | A rising breath, then it lands and settles | patch, blast, geyser, strike, spring, glyphs, lens, turret |
| Wall | Grinds up and thuds | wave, arcwall, drawnwall |
| Conjure | A blade drawn, a glint | guard, weapon, wand |
| Self | Drawn in toward you, rising | self, ward, aura, double |

A mix keeps at most three elements, lead on top, because a fourth layer turns to mush.

**The trade-off:** composing gives breadth and readability, but no single spell gets a hand-crafted sound. Spells that deserve one can get one later as an override, without changing the system.

## The engine

All in `game/packages/client/src/audio/`. Nothing in the sim changed. The golden hash is still `afcc1d3f`.

- `recipes.ts`: elements, shapes, and every sound as data. Pure.
- `variation.ts`: rune scaling, room profiles and impulse responses, pan, distance, occlusion, jitter, the limiter. Pure.
- `synth.ts`: code-made sounds, as pure DSP, seeded. The same bytes in the game, the gallery and the tests.
- `director.ts`: sim events and state to sounds. No Web Audio, so it runs in node with a fake sink.
- `engine.ts`: the Web Audio graph. It takes any `BaseAudioContext`, so the checks render the real graph offline.
- `game-audio.ts`: unlocks on first input, loads the bank, saves volumes.
- `gallery.ts`: the same code wrapped for the page.

**Rollback safety** follows `art/vfx.ts`:
- One-shots come from shown steps only, so a replay can't play anything twice.
- A replay can reveal events nothing has played yet (a remote cast that arrived late). `replayStep` keeps those, and `postRewind` plays them. An event counts as already heard if one of the same kind by the same body sounded within 6 ticks, because a corrected step moves things by a tick or two.
- Sustained sounds aren't started or stopped by events. Each frame lists what the state says should be sounding, and `LoopTable` works out the difference. A corrected prediction shows up as a fade (90 ms), never a click or a stuck loop, and a late remote channel simply starts. A loop's id includes what it's made of, so a spell that turns out to be another spell crossfades. A loop may vanish for two frames and be forgiven.
- State-change sounds (enemy attack beats, missiles landing, walls breaking) compare against the last shown step, so a change made inside a replay is heard at the next shown step.
- A mispredicted one-shot that never really happened can't be taken back. It's a short sound, so we accept that.

The rollback tests were checked by breaking the code on purpose in four ways (replays always new, late events dropped, replays playing at once, loops never stopping). The tests caught all four.

**The first input must stay cheap.** Making an `AudioContext` blocks the main thread while it opens the device: 422 ms here on its own, and 1.3 s for the whole start-up when it ran inside the first key press. In an online match that's a page frozen for over half of the 2.5 s drop-out, and `check:net` began failing now and then at exactly that moment (a rejoined page's first click). A suspended context can be made and clips decoded before any input, so all of that now happens in idle time after boot, and the first input only resumes. The worst stall is now about 50 ms, and `check:sound` fails above 400 ms. Headless runs still prepare on input, so they don't pay for sound they never play.

**Variations**, on every sound:
- **Runes:** 1 to 5 lower the pitch (about half an octave across the range), lengthen the body, add a sub thump and fill more of the room.
- **Rooms:** one convolver with a generated impulse response. Hall (Sanctum, and any room not listed, so the Academy gets it), cave (the tutorial's chamber), outdoor (Arena, Survive). `ROOM_ENV` in `variation.ts` maps rooms to profiles.
- **Interactions:** cancel, douse, steam, freeze, shatter.
- **Occlusion:** a line from your wizard to the sound, counted against `w.walls`. Rock counts 1; a barrier or curtain 0.4. Each rock wall halves the level and dulls it hard. The room's reverb drops less than the dry sound, since it comes round the wall.
- **Space:** pan and distance from the camera. Full volume within 11 u, then falling.
- **Repeats and crowds:** random pitch (±90 cents) and level on every play, a random clip that avoids the last one, per-group gaps and ceilings, at most 8 new sounds a frame, and a group turns itself down as it crowds. A voice cap of 28 and a limiter on the master catch the rest.

**Performance:** no measurable cost. Survive wave 12, sound off and on, run in turn under the same machine load: mean frame 56.4 and 60.2 ms off, 59.0 and 59.3 ms on, and allocation ranges that overlap (1181 to 1668 KB a frame off, 1162 to 1709 on). Comparing against an earlier run misleads, because load from other work on this machine moved the sim's own step time by three times. `npm run perf -- --sound` turns sound on, since a headless run has no input to start it. Compiling the held spell every frame was the one real cost found, and it's cached.

## Sounds and licences

`game/content/audio/README.md` has every source, with its URL, author and licence. In short: 65 tuned clips and 28 code-made ones. The recordings are Kenney (CC0) and Wikimedia Commons (public domain or CC0).

What sourcing turned up:
- **OpenGameArt isn't available to agents.** Its robots.txt disallows `Claude-Code`, `Claude-User` and `ClaudeBot` by name. One plain curl of a page had gone through before that was read; nothing from the site was kept or used, and no more requests were made. The user can download packs by hand.
- **kenney.nl refuses scripted downloads.** The licence was read on its pages, and the files came from an unmodified public copy on GitHub with Kenney's licence file. No request was disguised to get past the refusal.
- **Commons rate-limits.** A burst got a 429 with `retry-after: 600`, which was waited out.

## What could and couldn't be verified

`npm run check:sound` renders all 82 sounds offline through the real graph in headless Chrome.

Measured, and passing: nothing silent, nothing clipping, lengths sane; 1 / 3 / 5 runes ring longer and weigh more; cave, hall and outdoor ring in the right order; walls are quieter and duller; in the game, every clip loads, voices play, none is missing; the first input doesn't freeze the page; volumes persist; the game runs with `?sound=0` and with no Web Audio at all.

Headless Chrome doesn't enforce the autoplay rule, even with `--autoplay-policy`, so the check plays that part itself: it makes every context start suspended, then confirms nothing resumes before an input and a key press does. A real desktop browser hasn't run this yet.

**Not verified, because it needs ears:**
- Whether anything sounds good, or like Magicka's feel.
- Whether the Commons clips were cut in the right place. Cuts were chosen from loudness and onset measurements. Any of them could be a cough or a thump. The "ice" comes from a recording labelled bones, wood, fire and ice.
- Whether loops have an audible seam. The code-made ones are tested; the sample loops are crossfaded but untested.
- Whether the elements can be told apart. By brightness and bass the closest pairs are Cold and Lightning, Life and Sigil, and Cold and Sigil.
- The mix balance. RMS levels were evened out, but ears weigh bright sounds differently.
- Whether the composed spells sound like one thing or like a pile of layers. This is the design's biggest risk.
- Water's recordings came out mostly rumble once their loudness was evened out, so they are high-passed. That was done from the numbers alone.

## Not done in stage 1

- Turrets, orbitals and glyphs going off have only their burst or hit sounds.
- Auras, wards and guards have no held hum.
- Footsteps are stone only, and goblin-sized enemies have none (a wave's feet would be noise). Surface-aware steps would fit puddles and ice.
- No music, though the bus and setting are there.
- Enemy voices are one recording set, pitched.
- Safari before 18.4 can't decode Ogg Vorbis, so it gets the code-made stand-ins (`STAND_INS` in `engine.ts`).

## Trying AI generation

The user's idea, and the obvious first step. Nothing was generated for this stage. In order of promise:
1. **Narration:** nothing free fits, and it's waiting on the user's lore anyway.
2. **Enemy voices:** the most limited set here. Goblin chatter would add a lot of the comic tone.
3. **Whichever elements rate worst.** Use the same recipe, swap the layer, and rate the two side by side. The bank makes that one line in `bank.json`.

Anything generated should get the same treatment as art: kept raw with a manifest, as in `content/generated/`, with the tool's terms read before it ships.

## Open questions

Each has a box on the gallery page. Unanswered means the pick stands.

1. **Feel** (`q-1-feel`): is this the right direction? *Pick:* keep it, and push the drier recordings further.
2. **Source** (`q-2-source`): recordings, code, or blends? *Pick:* blends for elements, code alone for the interface.
3. **Element identity** (`q-3-element-identity`): can you name all nine with your eyes shut? *Pick:* listen to the measured close pairs first; move them apart in pitch before replacing anything.
4. **Variations** (`q-4-variations`): which earn their place? *Pick:* keep all four, with rune count the strongest.
5. **AI effects** (`q-5-ai-sfx`): what to try first? *Pick:* narration, then the weakest elements and enemy voices.
